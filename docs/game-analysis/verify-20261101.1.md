# D2 Survivors 20261101.1 唯讀相容性比對

日期：2026-11-01；對象：20261030.2 → 20261101.1。僅檢查提供的前端包及 web 工具；未修改專案或使用真實存檔執行遊戲。

## 結論與優先順序

1. **高：藥水與採買**。自動喝血只認 `potion`／`healing`／`rejuvenation`，目前不會刻意把 `mana` 當回血；但無藥帶資料時的數字鍵備援無法辨識種類。採買找不到生命藥時會退回第一個可買藥水，可能誤買魔力、解毒或解凍藥。拾物過濾忽略 `mana` 和 `rejuvenation`。應依種類識別，未知時停止猜測，依藥帶實際 `rows` 與可疊放種類判斷空間，另設法師魔力使用與採買策略。
2. **高：排行榜合規**。新版快照包含全部 Charsi ranks，但本機前端沒有證明伺服器的「可負擔」上限公式；在取得伺服器實作或官方精確公式之前，不可宣稱某組 ranks 可上榜。可以計算商店購買總價供提示，不能用它獨自宣稱合規。
3. **中高：裝備評分**。`heroNumbers` 新增 `Defense`，原評分沒有讀取，且 `Enhanced Defense` 的直接加權可能與 Defense 重複。應以攻擊等級、角色與怪物等級估計物理攻擊命中率，再比較預期承傷；先將直接 `Enhanced Defense` 加分移除或大幅降低。減傷與抗性依不同傷害類型保留獨立權重，避免把迴避套到法術或所有傷害上。
4. **中：技能變體資料**。現行 `modDefs` 特徵碼在兩版原始包均未命中，而它被列為可選；應追查資料注入／擷取鏈並檢驗技能修改頁，不能以引擎可啟動推論此功能正常。
5. **中：更新版本警示、測試及恐懼策略**。輔助器 `TESTED_GAME_BUILD` 仍為舊版；完成實際相容驗證後才更新。以新掉落、藥帶、命中率、恐懼層獎勵與完整角色流程做實機測試，再調整刷層策略。

## 防禦與傷害

G新:102264 的角色面板新增 `Defense`（`num: ut(e)`），描述其來自護甲、四分之一敏捷及技能百分比，怪物攻擊命中率下限 5%、上限 95%。`Damage Reduced` 同處以 `1-gt(e)` 輸出，描述來源為裝備、Charsi、Fade、Bone Armor，最高 50%；官方更新另指出 Battle Orders／Werewolf 不再提供該減傷。`heroNumbers` 回傳統計項目由 G新:386619 組裝。`autobot.js:735-750` 目前使用傷害、生命、Damage Reduced、抗性及 Enhanced Defense，完全未讀取新 `Defense`。

建議使用參考怪物攻擊等級與等級，按遊戲實際命中公式比較兩套裝的物理攻擊期望承傷；因目前未核對完整命中公式、物理／元素分布，沒有足夠證據給出通用固定權重。`autobot.js:170-192` 的威脅預估也沒有重現命中機率與完整防禦，應維持保守並標示估算，不宜因高防就認定單次攻擊不會命中。

## 藥水、採買與掉落

- I新:312935 列出 `potion`、`rejuvenation`、`healing`、`antidote`、`thawing`、`mana`。`potion` 是掉落生命藥；`healing` 是商店生命藥；`mana` 為新魔力藥。魔力藥等級名稱及基礎值依序 Minor 20、Light 40、Mana 80、Greater 150、Super 250；實際恢復依職業倍率，法師為 2（I新:312935、313402、332791）。
- 腰帶四欄、各欄容量 `rows`，相同種類才可堆疊，空欄可放新種類；喝取從指定欄 `shift()`，I新:314317。G新:382713 `drinkFrom(index)` 只在 playing、有效欄且非禁藥時消耗頂端藥水，並依種類套用效果；它不接受「我要血水」的種類參數。
- I新:332222：地上 `mana`、`potion`、`rejuvenation` 在適當狀況入腰帶，否則即時使用；魔力補充 `world.mana` 與 `world.shield`（各自存在時），且各自封頂，不能只以輔助器顯示的 `world.mana` 判斷護盾。`autobot.js:204-215` 已排除 `mana`，但 `217-218` 盲按備援有風險；`301-307` 未主動追蹤藍水與回復活力藥，`306` 硬編碼 4 也與 `rows` 不符。
- S新:42920 顯示阿卡拉商品清單僅法師加 `mana`；G新:362329 組商品，S新:42920 附近顯示購買單價 1000 及容量檢查。`autobot.js:874-883` 的描述文字判斷有在地化風險，備援會買任一藥水。建議以遊戲種類索引或可驗證商品識別分類，不用第一件藥當生命藥；保留生命藥所需空欄，給法師設定魔力藥目標，避免買滿後無法放回血藥。
- I新:328637 新增怪物掉藥判定：排除 `actBoss`、`breakable`，總門檻 `.053/4 = 0.01325`；法師依關卡比率把這機率分配至生命及魔力，其他職業只有生命部分。桶罐法師藍水另由 I新:328637 的 `qv` 分支處理。此為靜態機率，不等於實測掉落率。

## Charsi ranks：能確定的公式與未知

- G新:218385 `Vk` 對每個已知 ware 限定普通 rank 為 `0..maxRank`，只有普通 rank 滿且該項支援 endless 才傳送 `extraRanks`，額外 rank 限 `0..999`；G新:222283 將結果作為 `hero.charsiRanks` 送出，包含全部 ware，不僅 Magic Find／Gold Find。G新:343301 從存檔 `ranks`、`extraRanks` 建立快照。
- S新:97924 起，商店第 k 個普通 rank（k 從 1 起）價格為 `Math.round(baseCost * k**1.5 / 10) * 10`；第 j 個額外 rank（j 從 1 起）價格為 `Math.round(lastNormalPrice * (1 + j/4)**2 / 10) * 10`。加總每個 ware 的普通與合法額外 rank 可得歷史購買價格；`baseCost`、`maxRank`、`endless` 取 S新:93194 的 rank 定義。注意 JavaScript `Math.round` 語義，處理畸形或無效欄位不能自行猜測。
- 新版本 `Game` 引用 S新 `Un` 本地旗標檢查（S新:5170），檢查點數、屬性、等級、時間、裝備、技能及傭兵；未在該函式中找到 ranks 預算判斷。全部提供的 JS 搜尋 `charsiRanks` 只有 Game 快照組裝位置，未找到與可負擔上限相關的客戶端函式。故**伺服器判定、金幣收入上限、起始資金、跨角色累積及容差均未知**；商店成本不是上榜可負擔金額公式。需要取得排行榜服務端程式或官方規格，並用合法邊界案例驗證，才能製作可靠合規檢查。
